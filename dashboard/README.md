# 🏙️ Urbanix — Geospatial Dashboard Module

The `dashboard/` subfolder contains the presentation tier and geospatial visualization services for the Urbanix platform. It provides a lightweight, asynchronous FastAPI web server that consumes Parquet feature stores and GraphX route recommendations, serving real-time RESTful APIs, Folium Leaflet heatmaps, and a modern browser console.

---

## 📁 Subfolder Contents

```
dashboard/
├── main.py                  # Core FastAPI application (data readers, REST APIs, Folium map builder)
├── requirements.txt         # Minimal pinned Python dependencies for this subfolder
├── README.md                # Subfolder documentation and usage guide (this file)
├── static/
│   └── index.html           # Dark glassmorphic frontend UI (KPI ribbon, iframe map, auto-polling)
├── tests/
│   ├── test_dashboard.py    # Pytest regression suite (12 unit and API contract tests)
│   └── smoke_test.py        # Standalone live HTTP smoke verification script
└── venv/                    # Dedicated Python virtual environment (ignored by Git)
```

### File Responsibilities

| File / Directory | Purpose & Scope |
| :--- | :--- |
| **`main.py`** | Standalone ASGI backend application. Resolves repository paths dynamically, scans Parquet tables afresh on every request (zero in-memory caching), computes authentic zone centroids from intersection data, and serves the REST APIs (`/api/predictions`, `/api/route`, `/api/map`, `/`). |
| **`static/index.html`** | Standalone vanilla HTML5, CSS3, and JavaScript interface. Embeds the Folium map in an isolated `<iframe>` to prevent Leaflet script conflicts and memory leaks. Polls the backend every 15 seconds with a concurrency lock and cache-busting timestamps. |
| **`requirements.txt`** | Strictly pinned dependencies required to run and test this subfolder (`fastapi`, `uvicorn`, `pandas`, `pyarrow`, `folium`, `requests`). Completely independent of PySpark, Scala, or Hadoop libraries. |
| **`tests/test_dashboard.py`** | Pytest test suite testing path resolution, Parquet file filtering, coordinate calculations, status thresholds, endpoint response contracts, and negative inputs. |
| **`tests/smoke_test.py`** | Live end-to-end verification script targeting an active Uvicorn server on `http://127.0.0.1:8000`. |

## 📥 Subfolder Input Contracts (Read-Only)

This module reads from three shared data sources located in the parent repository:

1. **`../data/feature_table/traffic/`**: Columnar Parquet feature table containing windowed traffic records. Scanned on each request to extract the latest micro-batch window velocity per zone.
2. **`../data/recommended_routes/`**: Columnar Parquet route snapshot generated by the GraphX Pregel routing engine. Contains shortest paths, reachability flags, and ETA minutes from Origin Node 1 to Destinations 1–20.
3. **`../data/intersections.csv`**: Coordinate registry containing latitude and longitude for the 20 road graph intersections, used to compute geographic centroids for Zones 1 through 5.

*Note: All upstream sources are strictly read-only. This subfolder never modifies, regenerates, or overwrites upstream Parquet tables.*

## 💻 Running the Dashboard

### Launching the ASGI Web Server
You can launch Uvicorn from the repository root or from inside `dashboard/`. `main.py` resolves all paths relative to `__file__`, ensuring consistent behavior regardless of launch location:

```powershell
# Option A: From repository root
.\dashboard\venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --app-dir dashboard

# Option B: From inside dashboard/
Set-Location "dashboard"
..\dashboard\venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000
```

## 🔌 API Endpoints Reference

The FastAPI application in `main.py` exposes four primary routes:

### 1. `GET /`
- **Description**: Serves the main web operations console (`static/index.html`).
- **Response Format**: `text/html; charset=utf-8`

### 2. `GET /api/predictions`
- **Description**: Scans `../data/feature_table/traffic/` afresh, selects the latest micro-batch window, and returns a JSON list of predicted speeds and Level of Service (LOS) statuses for all 5 zones.
- **Response Format**: `application/json`
- **Sample Output**:
  ```json
  [
    {
      "zone_id": "zone_1",
      "zone_name": "zone_1",
      "window_start": "2012-03-01 08:05:00",
      "window_end": "2012-03-01 08:10:00",
      "predicted_speed_kmph": 77.67,
      "status": "Optimal",
      "status_color": "#10b981",
      "traffic_record_count": 5,
      "latitude": 34.0275,
      "longitude": -118.2770,
      "predicted_pm25": null,
      "model_provenance": "LinearRegression_MLlib"
    }
  ]
  ```

### 3. `GET /api/route`
- **Description**: Scans `../data/recommended_routes/` afresh and returns optimal shortest paths and ETAs from Origin Node 1 (Civic Center) to destination intersections.
- **Optional Query Parameter**: `?destination_id=15` (filters result to a specific destination).
- **Response Format**: `application/json`
- **Sample Output**:
  ```json
  [
    {
      "origin_id": 1,
      "destination_id": 15,
      "path": [1, 2, 14, 16, 15],
      "path_formatted": "1 -> 2 -> 14 -> 16 -> 15",
      "total_travel_time_hours": 0.317,
      "total_travel_time_minutes": 19.02,
      "is_reachable": true,
      "computed_at": "2026-10-22T08:05:00",
      "prediction_zones_used": 5,
      "fallback_applied": false
    }
  ]
  ```

### 4. `GET /api/map`
- **Description**: Dynamically compiles and returns an interactive Folium Leaflet HTML map document centered on the Los Angeles freeway network (`34.018° N, -118.236° W`), featuring OpenStreetMap tiles, zone centroid circle markers colored by speed, interactive popups, and a floating legend.
- **Response Format**: `text/html; charset=utf-8`

## 🛡️ Error Taxonomy & Graceful Degradation Contract (Day 11 — Phase 4)

The dashboard implements an enterprise-grade error taxonomy and graceful degradation model across all endpoints. Real HTTP error codes are strictly preserved (no masking real failures with false HTTP 200s), while client-safe structured JSON error envelopes prevent sensitive local path or stack trace leakage.

### 1. Structured Error Response Envelope

All error responses from the FastAPI backend conform to a standardized schema:

```json
{
  "error": "DATA_SOURCE_UNAVAILABLE",
  "message": "Traffic predictions data source is temporarily unavailable.",
  "detail": "Traffic feature store directory is missing.",
  "status_code": 503
}
```

| Field | Type | Description |
| :--- | :--- | :--- |
| `error` | string | Stable, machine-readable `ErrorCode` string enum. |
| `message` | string | Safe, human-readable high-level explanation suitable for user display. |
| `detail` | string / array / object | Contextual details without exposing sensitive filesystem paths or tracebacks. |
| `status_code` | integer | Numeric HTTP status code matching the response header. |

### 2. Error Taxonomy Matrix

| Scenario | HTTP Status | ErrorCode | Backend Behavior | Frontend Presentation |
| :--- | :---: | :--- | :--- | :--- |
| **Missing Feature Table Directory** | `503` | `DATA_SOURCE_UNAVAILABLE` | Logs internal path server-side; returns safe structured 503 without local paths. | Displays friendly warning banner: *"Traffic predictions are temporarily unavailable."* Retains last-known cached values if available with `Cached (API Down)` badge. |
| **Empty Feature Table (0 rows)** | `200` | *None* (`[]`) | Returns HTTP 200 with an empty JSON array `[]`. Does not fabricate zone readings. | Displays `0 Active`, `-- km/h`, `No Data`, and notice: *"ℹ️ No data yet. Awaiting sensor micro-batch streaming output..."*. |
| **Corrupted Parquet Data** | `500` | `DATA_PARSING_ERROR` | Catches PyArrow/FastParquet parsing exceptions, logs diagnostic with traceback, returns safe 500. | Informs user that data parsing failed; falls back to cached values if available. |
| **Invalid Schema (Missing Columns)** | `500` | `INVALID_DATA_SCHEMA` | Rejects DataFrame missing mandatory schema columns (e.g. `zone_id`), returns structured 500. | Retains cached state; logs schema failure server-side. |
| **Missing Route Snapshot Directory** | `503` | `ROUTES_UNAVAILABLE` | Returns structured 503 for `/api/route`. `/api/map` gracefully falls back to base geographic map with legend showing `[Route Unavailable]`. | Sets route badge to `Route: Unavailable`. Map renders cleanly without crashing or drawing broken lines. |
| **Empty Route Table (0 rows)** | `200` / `404` | `DESTINATION_NOT_FOUND` | `/api/route` returns `[]`. Query for specific destination returns 404 with structured envelope. | Chip displays `No Routes`, badge shows `Route: No Data`. |
| **Missing Intersections Registry** | `200` (Map) | *None* | Map falls back to base Los Angeles heatmap. Missing node coordinates safely abort PolyLine drawing. | Base map renders without route overlay; avoids partial or misleading lines. |
| **Invalid Destination Query** | `404` | `DESTINATION_NOT_FOUND` | Returned when requested destination ID does not exist in routes snapshot. | Displays not found notification for queried route. |
| **Malformed Query Parameter** | `422` | `UNPROCESSABLE_ENTITY` | Pydantic/FastAPI validation error standardized into structured JSON envelope. | Logs validation error cleanly without server crash. |
| **Unexpected Internal Exception** | `500` | `INTERNAL_SERVER_ERROR` | Global exception handler logs full critical traceback server-side and returns generic 500. | Displays system error banner; zero stack traces or secret data leaked to browser. |

### 3. Freshness & Cache Semantics During Outages

- **Independent Resilience**: Traffic prediction outages and routing engine outages fail independently. A failure in `/api/route` never disables prediction cards, and vice versa.
- **Epistemic Honesty for Cached Values**: When an endpoint becomes unavailable after previously succeeding, the frontend preserves the last known valid values and marks them `Cached (API Down)`. Their original source timestamps and calculated ages are preserved. Cached values are **never** treated as fresh simply because the cache was read.
- **Safe Recovery**: When downstream data pipelines recover and endpoints return fresh data, the frontend seamlessly transitions back to normal operating status (`Fresh` or `Stale` depending on actual data age) without requiring page reload.

## ⚙️ Architecture & Design Notes

1. **Zero In-Memory Caching**: `main.py` reads Parquet datasets directly on every HTTP request. It does not cache DataFrames in memory, guaranteeing that new data written by upstream streaming jobs is immediately visible.
2. **Parquet Checksum & Metadata Filtering**: Spark writes non-data commit markers (`_SUCCESS`) and checksum files (`.crc`) to output directories. Calling `pd.read_parquet()` directly on such directories fails with a PyArrow "magic bytes" error. `main.py` uses `get_parquet_files()` to filter for valid `*.parquet` files only.
3. **Data Freshness & Staleness Thresholds (Day 11 — Phase 3)**:
   - **Production Cadences**:
     - Routes: `ROUTES_UPDATE_INTERVAL_SECONDS = 60` (GraphX SSSP recomputation ~1 minute).
     - Predictions: `PREDICTIONS_UPDATE_INTERVAL_SECONDS = 300` (Spark 5-minute tumbling windows).
     - Staleness Multiplier: `STALE_THRESHOLD_MULTIPLIER = 3`.
   - **Configured Staleness Thresholds** (Multiplier applied exactly once):
     - **Routes Staleness Threshold**: $60 \times 3 = 180$ seconds.
     - **Predictions Staleness Threshold**: $300 \times 3 = 900$ seconds.
   - **Browser Consumer Cadence**: The browser dashboard polls every 15 seconds (`REFRESH_INTERVAL_MS = 15000`), which is strictly decoupled from the upstream data production cadences.
   - **Visual Indicators**:
     - When route data is stale ($\ge 180$s), the Folium PolyLine turns gray (`#6B7280`) and displays a `STALE ROUTE` tooltip and popup alert.
     - When prediction data is stale ($\ge 900$s), top-bar status badges and zone chips display visible `STALE` warnings.
   - **Timezone Safety**: All timestamps are normalized to UTC ISO 8601 strings (`YYYY-MM-DDTHH:MM:SSZ`). Naive timestamps from Parquet are explicitly localized to UTC. Future timestamps exceeding skew tolerance ($-5.0$s) are flagged as `FUTURE_CLOCK_SKEW` and marked stale to prevent negative age from remaining fresh indefinitely.
4. **Iframe Isolation**: Folium maps are loaded inside an `<iframe>` in `static/index.html`. Under W3C HTML5 security rules, script tags inserted via `innerHTML` do not execute. The iframe guarantees clean Leaflet script execution and automatic DOM/memory recycling on each 15-second refresh.
5. **Resilient Polling & Graceful Degradation**: The frontend uses `setInterval` set to 15,000 ms (15 seconds), equipped with a concurrency mutex (`isRefreshing`) to prevent overlapping requests and cache-busting query strings (`?t=Date.now()`). If an API fails transiently, last-known values are preserved and marked `Cached (API Down)`.

## 🔧 Subfolder Troubleshooting

| Issue | Cause | Fix |
| :--- | :--- | :--- |
| **`[Errno 10048] address already in use`** | Another process is occupying port 8000. | Stop the existing process or launch Uvicorn on a different port: `--port 8080`. |
| **`HTTP 503 DATA_SOURCE_UNAVAILABLE`** | `../data/feature_table/traffic/` is missing or contains no Parquet files. | Ensure the upstream pipeline has populated the feature table directory. Check server logs for internal path diagnostics. |
| **`HTTP 503 ROUTES_UNAVAILABLE`** | `../data/recommended_routes/` is missing or contains no route Parquet chunks. | Ensure the GraphX routing module has published route recommendations. |
| **`HTTP 500 DATA_PARSING_ERROR`** | Parquet file on disk is truncated or contains corrupted byte streams. | Re-run upstream Spark job or inspect directory for corrupt `.parquet` files. |
| **`HTTP 500 INVALID_DATA_SCHEMA`** | Parquet schema missing required columns (`zone_id` for predictions, `destination_id`/`path` for routes). | Verify upstream Spark schema definition. |
| **Blank map in browser** | JavaScript blocked or iframe path resolution issue. | Ensure internet access is available for Leaflet CDN assets and inspect browser DevTools (`F12`) console. |
